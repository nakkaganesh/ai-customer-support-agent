# AI Customer Support Agent

An AI-powered customer support system built using LangChain, OpenAI, FastAPI, MySQL, Pinecone, and Streamlit.

The application combines an LLM agent, business database tools, retrieval-augmented generation (RAG), conversation memory, authentication, and customer-level authorization to answer customer questions, retrieve order information, search company policies, and create support tickets.

## Features

- AI customer support agent using LangChain
- OpenAI GPT-4o-mini integration
- Tool calling for business operations
- Customer and order lookup
- Product information lookup
- Support ticket retrieval and creation
- Pinecone-based RAG for company policies
- OpenAI embeddings for semantic search
- Conversation memory using LangGraph `InMemorySaver`
- FastAPI REST API
- Streamlit chat interface
- API-key authentication
- Customer-level authorization
- Trusted customer identity using `ContextVar`
- Pydantic request validation
- MySQL persistence with SQLAlchemy ORM
- Docker support
- Automated tests with pytest

## How It Works

A customer sends a message through the Streamlit interface.

The request is sent to the FastAPI `/chat` endpoint with an `X-API-Key`.

FastAPI authenticates the API key and determines the corresponding customer identity. The authenticated customer ID is stored in a request-scoped `ContextVar`.

The LangChain agent receives the customer's message and decides which tools are required.

For customer-specific operations, the tools obtain the trusted customer identity from the backend context instead of accepting a `customer_id` generated by the LLM.

This prevents the model from selecting another customer's identity when accessing protected resources.

Depending on the question, the agent can use:

- database tools for customers, orders, products, and support tickets
- the RAG knowledge tool for company policies

The final response is returned through the API to the customer.

## Agent Tools

The agent can use the following tools:

### `lookup_order`

Retrieves an order belonging to the authenticated customer.

### `lookup_customer`

Retrieves the authenticated customer's account information.

### `lookup_product`

Retrieves product information such as name, category, price, and stock.

### `lookup_customer_tickets`

Retrieves support tickets belonging to the authenticated customer.

### `create_ticket`

Creates a support ticket for the authenticated customer.

The authenticated `customer_id` is obtained from backend context and is not exposed as an LLM tool argument.

### `search_company_knowledge`

Searches the company knowledge base for information about:

- returns
- refunds
- shipping
- warranties
- replacements
- related company policies

## RAG Pipeline

Company policy documents are stored in:

```text
data/knowledge/
```

The current knowledge base contains policy documents covering:

- refund policy
- replacement policy
- return policy
- shipping policy
- warranty policy

Documents are split using `RecursiveCharacterTextSplitter` with:

```text
Chunk size: 500
Chunk overlap: 100
```

Embeddings are generated using:

```text
text-embedding-3-small
```

The vectors are stored in the Pinecone index:

```text
customer-support-policies
```

For policy questions, the retriever performs similarity search and returns the top relevant policy chunks to the agent.

## Database

The application uses MySQL with SQLAlchemy ORM.

The data model includes:

- Customers
- Products
- Orders
- Order Items
- Support Tickets

Customer-specific database operations enforce authorization using the authenticated customer identity.

For example, order lookup verifies both the requested order ID and the authenticated customer before returning the order.

## Authentication and Authorization

Protected API requests require:

```text
X-API-Key
```

API keys are loaded from environment variables rather than stored in source code.

After authentication, FastAPI maps the API key to a customer identity.

The authenticated customer ID is stored using Python's `ContextVar`, allowing protected tools to obtain the trusted identity directly from backend context.

This design means the LLM does not control the customer identity used for protected operations.

The project includes tests verifying that:

- missing API keys are rejected
- invalid API keys are rejected
- customers can access their own orders
- customers cannot access another customer's orders
- order lookup requires authentication
- ticket creation requires authentication
- `customer_id` is not exposed in the ticket-creation tool schema

The API validates:

```text
message:   1-4000 characters
thread_id: 1-100 characters
```

## Conversation Memory

Conversation state is maintained using LangGraph:

```text
InMemorySaver
```

Each conversation uses a `thread_id`, allowing the agent to maintain context across messages within the running application.

Because the current implementation uses in-memory storage, conversation state is reset when the application process restarts.

Never commit the `.env` file to Git.

## Installation

Clone the repository:

```bash
git clone https://github.com/nakkaganesh/ai-customer-support-agent.git
cd ai-customer-support-agent
```

Install the locked dependencies:

```bash
uv sync --locked
```

Configure the required environment variables in `.env`.

## Build the Knowledge Base

After configuring OpenAI and Pinecone credentials, ingest the policy documents:

```bash
uv run python -m ai_customer_support_agent.rag.ingest
```

## Run the FastAPI Backend

```bash
uv run uvicorn ai_customer_support_agent.api.app:app --reload
```

The API runs locally at:

```text
http://127.0.0.1:8000
```

Interactive FastAPI documentation is available at:

```text
http://127.0.0.1:8000/docs
```

## Run the Streamlit Interface

With the FastAPI backend running, start the Streamlit UI in another terminal:

```bash
uv run streamlit run src/ai_customer_support_agent/ui/app.py
```

The Streamlit client communicates with the FastAPI `/chat` endpoint.

## Docker

Build the FastAPI backend image:

```bash
docker build -t ai-customer-support-agent .
```

Run the container with the required environment configuration:

```bash
docker run --env-file .env -p 8000:8000 ai-customer-support-agent
```

The Docker image runs the FastAPI backend on port `8000`.

The Streamlit interface is run separately.

## Current Limitations

This project is designed as a portfolio implementation of an AI customer support architecture.

Current limitations include:

- conversation memory is stored in process memory and resets after restart
- authentication uses environment-configured API keys rather than a full identity provider
- the Streamlit interface currently acts as a lightweight local client
- the Docker image runs the FastAPI backend; the Streamlit frontend is started separately

These choices keep the project understandable while demonstrating agentic AI, RAG, database integration, API security, authorization, testing, and containerization.
